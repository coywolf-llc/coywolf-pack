# AI Enrichment

[Coywolf Pack documentation](README.md) · [Getting started](../README.md#getting-started)

Ported from Coywolf SEO's AI features, with the same prompts and validation:

- **Entities for schema** (`ai.entities`). The model lists the people, organizations, places, and things a page is about, without identifiers. Each name is looked up on Wikidata (`wbsearchentities`), and only items whose label or alias is that name (ignoring case, accents, and punctuation) count. When several match, the model may only pick one of them. Each chosen item's `instance of` (P31) claims are then checked (one Wikidata Query Service request per entry for all its items): disambiguation pages are dropped, a Person must be human, an Organization or Place can't be a creative work (the album instead of the band), and an Organization can't be a place. The JSON-LD `name` is Wikidata's label. The result is stored per entry as Schema.org `about` (main subjects) and `mentions`, each with `sameAs` links to Wikidata, Wikipedia, and the official website (P856) when there is one. Coywolf's Schema module reads them with `getEntryEntities(ctx | db, collection, id)` from `src/ai/entities.ts`.
- **glossary.io definitions** (`ai.glossary`, on by default). When an entity's Wikidata ID has a definition on [glossary.io](https://glossary.io), its node gets that page last in `sameAs` (for example `https://glossary.io/gemini/`), the glossary's short definition as its `description` (the stored description stays when there isn't one), and since 0.46.0 glossary.io's names for it other than the entity's own as `alternateName` (the term's glossary name and its "Also known as" names: X gets "Twitter", Wikidata's "search engine optimization" gets "SEO"). glossary.io lists every term with a Wikidata ID in one index, `https://glossary.io/api/entities.json` (`{v: 1, terms: {QID: [slug, definition, names]}}`, about 1,000 terms, 80 KB compressed). The site stores a copy in plugin storage (`aiGlossary`, document `index`), and each isolate keeps it in memory for an hour. glossary.io is asked only when the site has no copy yet (the first render that needs it waits up to 1.5 s, so pages don't go into the edge cache without it) and, after the response, when the copy is a day old: about one request a day per site, and none on days nothing renders. If glossary.io fails, the page renders with the copy it has (or without glossary data) and stays cacheable; that isolate tries again after 10 minutes, then 20, 40… up to a day while it keeps failing, logging each failure. An answer with no terms counts as a failure, so it never replaces a good copy. Requests carry `User-Agent: CoywolfPack/<version>`. Pages already in the edge cache pick up changes when they render again. It's never used on glossary.io itself. With a D1 database instead of the plugin context (`getEntryEntities(db, …)`), only a copy the site already stored is used. A copy stored by 0.45.0 (no names) is refreshed after the first response that needs it. Code: `src/ai/glossary.ts`.
- **glossary.io links** (`ai.glossaryLinks`, off by default; since 0.49.0). After an entry's entities are found, each one with a glossary.io definition gets one link to it in the entry's text, and the entry is republished. It runs after a first analysis and after one whose text changed since the links last looked, never after a re-analysis for new settings. Entries analyzed before the part was turned on are linked with **Link existing entries** (below); without it, their first text change after the part is on only records their text (it can't be told apart from a re-analysis for new settings), and the next one links. The rules (`src/ai/glossary-links.ts`):
  - An existing glossary.io link to the term: nothing to do. Otherwise the first link whose text is one of the entity's names (its Schema name or glossary.io's names for it, ignoring case and hyphens; a plural only for concepts and abbreviations) is switched when it's an identity link: the entity's Wikipedia article or Wikidata item, a site's home or about page, its official site (a deeper page only when the path names it, like `yoast.com/wordpress/plugins/seo/` for Yoast SEO), a social profile, or a page on a site named after it (`apple.com/apple-music/`).
  - Never switched: links to the site itself or its other domains, affiliate links (`/visit/…`, `/ref/…`, affiliate networks and short links, referral parameters, fragments and landing subdomains like `try.` and `go.`), citations (docs, help and sign-up subdomains, articles, issues, dated or deep paths, queries and fragments), a Wikipedia link on a claim rather than the name, a link whose text is a domain ("create an account at mastodon.social"), a name inside a longer name ("Shopify" in "Shopify Unite"), and a profile link in a list item.
  - An entity named by an affiliate link gets no glossary link in that entry, so nothing competes with the affiliate link: when the link's text is the entity's name, or mentions it and the link is for it (its brand matches, like `shopify.pxf.io` for "Shopify free", or the destination is unknown, like an Amazon short link). "Pressable WordPress hosting" doesn't rule out WordPress.
  - Otherwise its first plain mention in a paragraph or list item is linked, with the text as written ("Progressive Web Apps", "filler words"). Not in headings, blockquotes, code, other links, handles, paths or domains, not part of a longer name ("Google" in "Google Search Console" or "Google I/O", "SMTP" in "Gravity SMTP", "Mail" in "Big Mail"), and not an abbreviation right after a different expansion ("neuro-linguistic programming (NLP)"). A mention at the start of a sentence or inside quotation marks is used only when there's no other.
  - What it remembers is kept per entry in its own storage collection (`aiLinks`), so a failed analysis or a trash and restore doesn't erase it: the Wikidata IDs it handled (each entity is linked at most once per entry, and a link removed by hand isn't added back), the text it last saw, and when to try again.
  - Safety: only published entries with no pending draft and no save in the last two minutes are edited; the entry is read again right before the write and left alone if anyone saved it; only the draft the edit made is published. Entries it had to leave (a draft, a recent save, a save in between, no glossary.io index yet, an error) are tried again by the scheduled run after 30 minutes, then 1, 2, 4, 8 and 16 hours, without a model call. If a save lands in the moment between the read and the write, nothing is published and it's logged as an error: check that entry's revisions. An edit whose publish didn't happen is recognized and published on the next try.
  - Site settings, in `coywolfPlugin({ ai: { glossaryLinks: { … } } })`: `ownHosts`, the site's other domains, never switched (the site's own host always counts; `"coywolf.*"` is every coywolf domain and its subdomains); `shortHosts`, the site's affiliate short-link domains (`["coywolf.io"]`); `skip`, entry slugs never linked (legal pages, link directories; `"posts:slug"` for one collection).
  - **Link existing entries:** `POST /_emdash/api/plugins/coywolf-pack/ai/glossary-links` with `{ keys: ["posts:<id>", …] }` (up to 25; 5 at a time is gentler, since each publish runs every module's publish hooks) or pages of analyzed entries (`{ limit, cursor }`) runs the same code. `dryRun: true` plans without writing (allowed with the part off), and `exclude: { "posts:<id>": ["Q123"] }` names entities never to link in an entry. It answers 409 while the scheduled AI run is working; try again a minute later. Republishing moves an entry's updated date, and a plugin can't set it back: if the theme shows it, restore it in the database afterwards. Code: `src/ai/glossary-linker.ts`.
- **Output entities on their own** (`ai.entitiesStandalone`). Adds the entities to the page's JSON-LD as a `WebPage` node (same `@id` as EmDash's `mainEntityOfPage`). Only for sites that don't use Coywolf Schema.
- **Meta descriptions** (`ai.descriptions`). Writes a description (under 155 characters, no clickbait) for published entries in SEO-enabled collections that don't have one. By default they're suggestions you edit and apply on the AI page; or have empty descriptions filled automatically. Either way it writes only EmDash's SEO panel field and never replaces a description someone wrote unless you choose **Replace**.
- **Image text** (`ai.imageText`). Writes alt text (and, if you turn it on, captions) for images on upload and in bulk, with accessibility-first prompts. When the image is used in a published entry (EmDash's media usage index, EmDash 1.5+), the model also gets that entry's title, the heading above the image, and about 900 characters of text on each side with the image's place marked, so the alt text and caption fit how the image is used there while still reading well on their own (about 450 more input tokens per image). Only published entries' text is sent; an image that isn't used in one is described on its own. An image analyzed on upload isn't in an entry yet, so it's described on its own; **Run bulk** (or **Analyze again**) after it's published gives it the article's context. Alt text and captions people wrote are kept unless you turn on overwrite. EmDash media has no title or description fields, so titles are shown on the AI page for reference only.

Apart from glossary.io definitions, they're all off by default, under the **AI Enrichment** switch on the **Features** page (**Coywolf Pack → Features** in the sidebar).

**In the entry editor.** While AI Enrichment is on, a saved entry's sidebar has an **AI suggestions** section (admins only): the suggested meta description with **Copy** and **Dismiss**, the entities found (main subjects highlighted), and **Analyze again**, which queues the entry. It doesn't write the description itself: paste it into the SEO section, or apply it on the AI page, so it can't clash with the editor's own save. It says so when the entry's collection isn't one AI Enrichment analyzes.

## How it runs

Saving, publishing, or uploading never waits on AI: hooks only add the entry or image to a queue (after a short wait, so a burst of saves becomes one job, and only when the entry's text actually changed). A scheduled job works through the queue every two minutes (or with each cron tick, if the site's cron runs less often), a few items at a time (**Items per scheduled run**; raise it on a site with a slower cron), and stops for the day at **Max model calls per day** (default 200; an entry costs up to three calls, an image one). Each run also stays under 40 outbound requests (model calls plus Wikidata lookups), so it fits the Workers Free plan's subrequest limit; entries and images take turns, so a backlog of one doesn't hold up the other. Failed items are retried after 5 and 20 minutes, then marked as errors; a retry reuses the model output it already paid for. Deleting an entry removes its analysis. **Run bulk** on the AI page queues every published entry (skipping unchanged ones) or every image without alt text. The AI page also has a connection test, the queue status, suggestions to review, the analyzed entities (with **Export CSV**: one row per entity with its Wikidata, Wikipedia and website links, plus each entry's AI description), and a 30-day usage log with token counts.

## Setup

Pick a provider on **Plugins → AI Enrichment → Settings**:

- **Cloudflare Workers AI** (the default when the binding exists). Add the binding to `wrangler.jsonc`:

  ```jsonc
  "ai": { "binding": "AI" }
  ```

  The default model is `@cf/meta/llama-4-scout-17b-16e-instruct` for both text and images. A different binding name goes in `coywolfPlugin({ ai: { binding: "MY_AI" } })`.
- **Anthropic, OpenAI, or Google Gemini** with your own API key (stored encrypted, so the site needs `EMDASH_ENCRYPTION_KEY`). Defaults (checked October 2026): `claude-sonnet-5-5`, `gpt-6-luna`, `gemini-3.8-flash`. To use another model, such as a cheaper one or a newer one after a default is retired, enter its id in **Text model** and **Image model** on the Settings tab; leave them blank to follow the defaults.

Images are sent to the model at up to 3.5 MB. With a Cloudflare Images binding (`"images": { "binding": "IMAGES" }`, the same one EmDash uses for resizing) larger images are downscaled to 1568 pixels first; without one they're skipped. SVGs are skipped.

Set `ai: false` in `coywolfPlugin()` to leave the module out entirely. The module declares the `network:request` capability (for `api.anthropic.com`, `api.openai.com`, `generativelanguage.googleapis.com`, `www.wikidata.org`, and `query.wikidata.org`), plus content read/write, publish and revision read (the SEO panel for descriptions; entries' text for glossary.io links, which reads a pending draft to tell its own unpublished edit from someone else's), schema read, and media read, bytes, and metadata write.

## Notes

- Only published entries are analyzed. Change the model or switch features and entries are re-analyzed the next time they're saved (or with **Re-analyze unchanged entries**).
- The daily limit is counted in UTC days. Each call's token usage is in the usage log; costs depend on your provider.
- Wikidata lookups are cached per Worker isolate and made one at a time, with `maxlag=5`. If Wikidata doesn't answer, the item is retried rather than saved unverified; if it asks to slow down (HTTP 429 or maxlag), every entity job waits for its `Retry-After` without counting as a failed attempt (after 10 waits in a row, the next counts as one). When an item lists several official websites, the preferred-rank one is kept, then https over http, then the first alphabetically.
