# Discovery

[Coywolf Pack documentation](README.md) · [Getting started](../README.md#getting-started)

Help search engines, feed readers and AI agents find your content. Ported from Coywolf SEO for WordPress (the RSS feed is new). Everything is off until you turn it on under **Plugins → Coywolf Pack**: the **Discovery** switch, then any of its four parts (here or with the switch next to each part's title on the Discovery page). Settings and status are under **Plugins → Coywolf Pack → Discovery**.

| Feature switch | Default | What it does |
| --- | --- | --- |
| `discovery` | off | Main switch for the module |
| `discovery.indexnow` | off | IndexNow submissions and the key file, plus Bing Webmaster API submissions once a key is saved |
| `discovery.newsSitemap` | off | `/news-sitemap.xml` |
| `discovery.feed` | off | RSS feed at `/feed/`, category feeds, and the `<link rel="alternate" type="application/rss+xml">` head tag |
| `discovery.llms` | off | `/llms.txt`, Markdown versions of entries, and the `<link rel="alternate" type="text/markdown">` head tag |

- **IndexNow**: when an entry is published, updated (in collections without draft revisions), unpublished, or deleted, its public URL goes to `api.indexnow.org` (or `www.bing.com`), which shares it with Bing, Yandex, Seznam, Naver, and the other participating engines. Changes made within 3 seconds of each other go out as one request, after the response is sent. A changed slug submits the old URL too. Entries set to noindex aren't submitted. The key is generated the first time it's needed (or when you open the Discovery page with IndexNow on) and served at `/<key>.txt`; **New key** replaces it. The page shows the last 25 submissions (one row per endpoint) and has **Submit home page** for checking the setup. Bing throttles IndexNow pings from Cloudflare Workers, so for Bing add a [Bing Webmaster API key](#bing-webmaster-api-key). While the site is in EmDash's staging mode (**Settings → General → Site Status**, EmDash 1.5+), hidden from search engines, nothing is submitted, **Submit home page** is refused, and the Discovery page says so; submissions start when the site goes live.
- **News sitemap**: entries published in the last 48 hours (the window Google News uses), newest first, at most 1,000, with publication name and language (defaults: site title and locale). Choose the collections (default: `posts`). Also served at `/coywolf-news-sitemap.xml`, Coywolf SEO's URL, so a sitemap submitted from WordPress keeps working. Submit it in Google Search Console; to list it in robots.txt, add `Sitemap: https://coywolf.com/news-sitemap.xml` to the custom robots.txt under **Settings → SEO**. The module doesn't change robots.txt.
- **RSS feed**: RSS 2.0 at `/feed/` (WordPress's feed URL) with the newest entries of the chosen collections (default `posts`, 20 entries, up to 100), each with its title, link, author (the first byline), publish date, category (its first term in the taxonomy its URL uses, or `category`), and summary (the `excerpt` field or SEO description). The channel has the site title, tagline, locale, and the site logo (or favicon) when it's a PNG, JPEG or GIF. Every page gets `<link rel="alternate" type="application/rss+xml" href="https://coywolf.com/feed/">` in the head, so feed readers, apps and bots find it. **Category feeds** (on by default): when a collection's URL override is a term then the slug (`urls: { posts: "/{termpath:category|uncategorized}/{slug}/" }`, or `{term:…}` or `{category}`, with an optional fixed prefix), each term's archive URL + `feed/` is that term's feed, including its child terms' entries (`/news/feed/`, `/news/seo/feed/`), titled "<term> Archives - <site>" as WordPress titles them. A path that isn't a feed (no such term) goes on to the site. Entries set to noindex aren't listed. Feeds are built when requested and kept in the edge cache (Workers Cache, with Astro route caching on) for up to an hour, tagged with their collections and taxonomy: EmDash clears those tags on every publish, live edit, removal and term change, and saving the Discovery settings clears all feeds, so a change shows up on the next request. Readers may keep their own copy for up to 15 minutes (`Cache-Control: public, max-age=900`). Paths that aren't feeds are remembered in each isolate's memory for a minute. `/feed` without the slash is left to the site (which redirects it to `/feed/`).
- **llms.txt** ([llmstxt.org](https://llmstxt.org/)): the site name, a summary (default: the site tagline), an optional introduction, then one list per collection (newest first, 100 per collection) and an **Optional** list for the rest, up to 500 entries (configurable up to 5,000). Each link points at the entry's Markdown version, or at the page itself when Markdown is off. Excerpts (`excerpt` field or SEO description) become link notes. A static `public/llms.txt` takes precedence, because Cloudflare serves static assets before the Worker runs.
- **Markdown versions**: each entry at its URL + `index.html.md` (`/blog/post/` → `/blog/post/index.html.md`, Coywolf SEO's convention). The Portable Text body becomes Markdown (headings, paragraphs, lists, links, images with captions, code, block quotes, tables, and horizontal rules; other blocks are skipped) under YAML frontmatter with the title, URL, dates, sources, and an optional license. There's no `Accept: text/markdown` negotiation on the entry's own URL: Cloudflare's cache key ignores `Accept`, so one such request could put Markdown into the cached HTML page. Responses carry `X-Markdown-Tokens`, an estimate at about 4 characters per token. Entry pages get `<link rel="alternate" type="text/markdown">` in the head.

Only published, non-noindex entries in routable collections are included. URLs come from EmDash's own routing (each collection's URL pattern, date tokens, locale prefix, and trailing-slash setting), so they match the native sitemap.

## Bing Webmaster API key

Optional, and recommended for Bing. Bing and `api.indexnow.org` throttle IndexNow pings sent from Cloudflare Workers: the requests leave from Cloudflare's shared egress IP addresses, and Bing answers `429 TooManyRequests` ("you have sent too many requests to us recently") however few the site itself sends. Every IndexNow submission from the pack's sites since October 11, 2026 got that 429, while the same request sent from another network got 202. Bing's URL Submission API is authenticated with your own key and has a quota per site, so with a key Bing gets your URLs reliably.

With a key saved, each batch of changed URLs, and **Submit home page**, goes to Bing's `SubmitUrlBatch` too. The IndexNow ping still goes out for Yandex, Seznam, Naver and the other engines. Both run at the same time after the response, each with a 10-second deadline, and each gets its own row in **Recent submissions** (**Bing Webmaster API**, or **IndexNow (api.indexnow.org)**), so an IndexNow 429 never hides Bing's result. Nothing changes on a site until a key is saved.

To get the key ([Microsoft's guide](https://learn.microsoft.com/en-us/bingwebmaster/getting-access)):

1. Sign in to [Bing Webmaster Tools](https://www.bing.com/webmasters) and add and verify the site, if it isn't there yet. The key works only for sites verified in the same account.
2. Select **Settings** (top right), then **API access**. The first time, accept the terms, then select **API Key**.
3. Select **Generate API Key** and copy it. Each account has one key, valid for all of its verified sites.
4. On **Plugins → Coywolf Pack → Discovery → IndexNow**, paste it into **Bing Webmaster API key** and select **Save key**. Saving checks the key right away and shows the site's quota.

- **Quota.** Bing allows a set number of URL submissions per site each day and each month. Before a submission the pack reads what's left (`GetUrlSubmissionQuota`) when its last reading is over an hour old or from an earlier day (UTC), counts it down as batches go out, and never sends more than it knows is left: the rest is logged as **Not sent**. When Bing answers that the quota is used up, later submissions wait for the next reading. Batches hold at most 500 URLs (the API's limit), and one submission's Bing calls end within 20 seconds (URLs left over are logged as **Not sent**). **Check key** shows the quota, or Bing's error: `InvalidApiKey` for a wrong key, `NotAuthorized` when the site isn't verified in the key's account.
- **Storage.** The key is a secret setting (`discoveryBingApiKey`), stored encrypted with `EMDASH_ENCRYPTION_KEY` like the pack's other API keys. The admin only learns whether one is saved; **Remove key** deletes it. It can also be set on EmDash's generic plugin Settings page. Bing's API takes the key in the request URL (`?apikey=`), so the pack never logs request URLs and removes the key from any error text it keeps.
- **Site URL.** Bing gets the site's origin (`https://coywolf.com`) as the `siteUrl`, which must match a site verified in the key owner's account.

## Setup

Nothing to configure beyond the feature switches. The module's site URLs are served by the pack middleware (see Redirects → Setup), so add `coywolfPack()` from `@coywolf/emdash/middleware` to `src/middleware.ts` if you haven't. The plugin asks for `content:read`, `schema:read`, `bylines:read` (feed authors), `network:request` (hosts `api.indexnow.org`, `www.bing.com`, and `ssl.bing.com` for the Bing Webmaster API), and `hooks.page-fragments:register`. A theme that has its own feed route or head link can drop them: the pack's middleware answers `/feed/` first, and the head link would be listed twice.

## Caching and limits

- llms.txt and the news sitemap are stored in plugin storage and visitors are always served the stored copy. Content changes (publish, unpublish, delete, or a live edit) and settings saves rebuild them in the background after the response, debounced by 5 seconds; a copy older than its limit (5 minutes for the news sitemap, whose window moves; 24 hours for llms.txt) is served once more while a background rebuild runs. Only the very first request, before anything is stored, builds inline. **Rebuild now** on the Discovery page rebuilds both immediately. Each Worker isolate also keeps responses for a minute (up to about 2 MB), and CDNs may keep `llms.txt` and `.md` files for an hour (`Cache-Control: public, max-age=3600`; 5 minutes for the news sitemap).
- Markdown URLs resolve through EmDash's routing (`resolveEmDashPath`, or `/{collection}/{slug}` for collections without a URL pattern), then are checked against the entry's public URL. Entries behind a locale prefix or a custom route don't get a Markdown version.
- An entry's old URL is known only if it was published while IndexNow was on, so unpublishing or deleting an entry published earlier submits nothing.
- The news sitemap has no category include/exclude filter (Coywolf SEO's WordPress option); pick collections instead. Coywolf SEO's AI entity sections (a Labs feature) aren't ported.
